# neuralnet.cpp v1.18.0 Release Notes

> **发布范围**：`v1.17.0`（tag `v1.17.0`，2026-11-08）→ `v1.18.0`（tag `v1.18.0`）。
> **主题**：**端到端训练性能提升**——host 侧（内存池保留 / 去重复 `zero_grad` / 线程池零堆分配）、
> 归一化双 kernel、f16 typed JIT 直通（边界 cast 回归根治）、fold 尾链与 GEMM swizzle 线；
> 叠加 offload f16、API 边界收敛与一批缺陷修复。
> **兼容性**：**含破坏性变更**（第 2 位递增）——`parse_precision_arg` 改名、`param_*_to_blob`
> 下沉 `detail`、`ComputeEngine` offload 偏移单位改为字节并增 `Precision` 形参、
> `nn_core` 不再导出 `engine/engine/include`；迁移指南见 §6。
> **验收基线**：见 §7（Release/Debug ctest 81/81、e2e 三配方、文档门禁）。
> **短概览（GitHub Releases）**：见本目录同号旁的发布页文案（单独短文，不替代本册）。

## 0. 亮点速览（TL;DR）

| 方向 | 变化 | 收益 / 结果 |
|---|---|---|
| **端到端 vs torch（主对比）** | 同配置 GPT d64/b64/s256，40HX，f32 | **109.2 → ≈65–67 ms/step**；对 torch fp32 53.5 的差距 **2.03× → ≈1.22×**（含 LN 与池修复） |
| 内存池保留阈值 + 空闲龄期 | `NN_POOL_RETAIN_MB` 默认 256；只归还整步未触碰的全闲块 | profile：`release_idle_pool_blocks` **10.0 → 1.07 ms/步（−89%）**；busy **78.4% → 91.1%**；e2e **65.3–67.3 ms/step**；释放耗时再 **−60%**（龄期） |
| 去重复 `zero_grad` | 删 `TrainingSession::begin_and_zero_`（update 起点冗余清零） | `engine.zero` **153 → 83 次/步（−70）**；`begin_batch` −1/步 |
| LN / RMSNorm 双 kernel 前向 | mean/var 链式 ColSum 单表达式 + γβ 第二 kernel；std 不物化 | 由 ≈7/9 段多 kernel 收成 **2 kernel**；`activation_cache` 改存 `input_cache_` |
| **f16 typed JIT 直通**（引擎） | 单表达式 / 图路径按签名直通 f16 读写，消 AOT 删除后的边界 cast 回归 | `--f16` e2e **138.8 → ≈103 ms/step（−26%，反超 f32）**；显存峰 **6972 → ≈2070 MiB（归一）**；全 f16 首步 OOM → **3 epoch 跑完** |
| fold 顶层逐元素尾链（P10-③） | `make_fold_rowsum_tail` / `col_reduce_sum` 导出 + validate / CPU / 图融合接线 | fold 后收尾可进同一表达式；`expr_fold_test` 尾链对拍 |
| 激活 offload 支持 f16（#P8） | slab 按激活**自身精度**存取（f16=2B/元素）；`offload_restore` 增 `Precision` | f16 激活 offload 宿主内存与 PCIe **减半**；配置期从「全 f32 才放行」放宽到 f16/f32 |
| GEMM swizzle / 分块线（引擎） | `matmul_tiled` bank swizzle + WIDE + fetch/commit；`batched_matmul` swizzle；`matmul_q_i8` 分块重写 | 同窗 A/B：方阵 4096³ **+3.0%**、head dgrad **+2.5%**；`matmul_q_i8` **500 → 4000 GFLOPS**（逐位不变）；e2e 走融合路径为主 |
| 线程池 / fold 热路径零分配（引擎） | 任务对象去 `std::function` 堆分配；fold chunk scratch 线程持久复用；键拷贝去除 | host 侧固定开销继续下探（busy 回到 91–93%） |
| API 边界收敛 | `parse_precision` 单一实现；`param_*_to_blob` 下沉 `detail`；宿主桥统一 `nn::` | 公开面零 `detail::` 符号；CLI 精度解析去重 |

## 1. 性能：与上一版、与 torch 的完整对比

### 1.1 口径

- **模型**：GPT，`d_model=64 / heads=4 / layers=4 / d_ff=256 / seq_len=256 / batch=64`（与
  [`../benchmarks/2026-11-12-vulkan-vs-torch.md`](../benchmarks/2026-11-12-vulkan-vs-torch.md) 同构）。
- **硬件**：NVIDIA CMP 40HX（8 GB）· Vulkan（nn）/ CUDA（torch）。
- **稳态**：3 epoch 的 epoch 2–3 平均；显存 PDH 整卡峰值（同轮口径）。
- **本版 e2e 复测**（history「池保留阈值」「host 残余清理」）：同配置 text_train，含 LN 双 kernel
  与池修复后的 **65.3–67.3 ms/step**。

### 1.2 与上一版（v1.17.0 / 2026-11-12 基准）对比

## 2. 主题能力（本版新增 / 行为变化）

### 2.1 内存池：保留阈值 + 空闲龄期

- `release_idle_pool_blocks` 进程内读一次 **`NN_POOL_RETAIN_MB`（默认 256，0=旧行为）**；
  释放后总空闲仍 ≥ 阈值时不归还整块。
- 龄期：只归还**上次 release 以来未被子分配过**的全闲块，消 WDDM 下 513MB 工作块
  「步末 free → 下步 alloc」抖动（单次 free/alloc 可达 5–17 ms）。
- 行为开关口径：读一次 + 缓存，不入探针编译门。

### 2.2 LayerNorm / RMSNorm 双 kernel 前向

- 前向收成 **E1（mean/var 链式 ColSum → normalized）+ E2（γβ）**；`std_inv` 不物化。
- backward 从 `input_cache_` 重算 μ/σ；`activation_cache()` 枚举从 `std_cache_`/`rms_inv_cache_`
  改为 **`input_cache_` + normalized/normed**。
- **对 offload 消费方可观察**：导出集合形状变化，但覆盖 backward 所需激活的契约不变。

### 2.3 TrainingSession：去掉 update 起点重复 zero_grad

- 删除 `begin_and_zero_()`；`finish_update_` 成功路径的 `zero_grad` 为唯一清零点。
- 失败路径仍由 `accumulation_dirty` 拦截到 reset。

### 2.4 激活 offload 支持 f16（#P7/#P8）

- slab 按激活**自身精度**记账（f32=4B、f16=2B，条目 8B 对齐）；`kOffloadSlabElemBytes` 容量契约。
- `offload_save`/`offload_restore`：`offset` → **`byte_offset`**；restore 增 **`Precision P = F32`**。
- CLI：`--activation-offload` 与精度组合校验从「仅全 f32」放宽到 **f16/f32 四槽均可**；
  仍拒绝 t1_58 / bf16 / f64。帮助文案已同步。

### 2.5 fold 尾链与 f16 融合（引擎 + 模块导出）

- P10-③：fold 顶层逐元素尾链（validate / v1/v2 发射 / CPU / 图融合）。
- 模块 `nn.expr` 导出 `make_fold_rowsum_tail`、`col_reduce_sum`。
- P10-④：f16 分量边界 cast 直发（图路径）。

### 2.6 f16 typed JIT 直通（引擎，根治 11-12 回归）

- 单表达式与图路径按签名 f16 直读直写、f32 算术，失败回退边界 cast + 负缓存。
- 详见 [`../benchmarks/2026-11-12-vulkan-vs-torch.md`](../benchmarks/2026-11-12-vulkan-vs-torch.md) §8。

### 2.7 GUI 实验选项面板

- `EXPERIMENTAL_OPTIONS`：env 注入（`NN_MM_KSPLIT_*` / `NN_FOLD_*_PROBE` 等），**不进 CLI flag**；
  探针开启时强制专用 `.nnk` 缓存防污染。与 `gui_cli_audit` fields 门禁零交集。

### 2.8 其它修复 / 加固

- tokenizer markers 改非 `static constexpr`（满 import 面下 clang 重复发射恒零失效，llvm#239625 同族）。
- `text_train` 预热失败改 `Result` 上抛（OOM 不再 fail_abort）。
- offload slab 容量 tripwire（`kOffloadSlabElemBytes` 同源）。
- Windows 退出期 `kernels_scratch` external 强引用释放（`0xc0000005` 根治，引擎）。
- `.nnk` 坏缓存隔离重建、字段长度校验、写盘失败降级告警（引擎）。
- clang BMI Debug CRT 镜像（`_DEBUG` + `msvcrtd`）消 IDL 链接失败。
- MSVC cl 模块 IFC 管线探索落地后按裁定回滚方案 A（见 history）；本机矩阵以 clang 为准。

## 6. 破坏性变更 + 迁移指南

| # | 变更 | 影响 | 迁移 |
|---|---|---|---|
| 1 | `nn::cli::parse_precision_arg` → **`nn::cli::parse_precision`** | 直接调用旧名编不过 | 改名；或改 include `cli/cli_precision.hpp` |
| 2 | `param_entry_to_blob` / `param_blob_to_entry` 下沉 **`nn::detail`** | 公开调用方需限定 detail 或改走 `save_model`/`load_model` | 序列化请用公开入口；宿主编解码属内部桥 |
| 3 | `ComputeEngine::offload_save/restore`：**偏移单位 float → 字节**；restore 增 `Precision` | 自算 float 偏移的调用方会写错位置 | 按字节传偏移；restore 传入与 forward 一致的精度 |
| 4 | `offload_*_impl` 虚函数签名同步 | 自定义引擎子类 | 覆写处改签名 |
| 5 | `nn_core` 不再提供 `engine/engine/include` 路径 | 依赖 LGPL 实现头的消费方 | 只 include 抽象层 + 主仓 `include/`（T9 边界） |
| 6 | `LayerNorm`/`RMSNorm` `activation_cache()` 内容 | 枚举依赖 `std_cache_` 的代码 | 改为 `input_cache_` + normalized/normed；契约仍是「backward 所需激活」 |
| 7 | `--activation-offload` × `--f16`：**由拒绝改为接受** | 行为放宽，非破坏 | 无需迁移；三值/bf16/f64 仍拒绝 |
| 8 | 模块导出增减（§3） | `import nn.*` 消费方 | 按需 using 新符号；删除的 `detail::` 转出口改用 `nn::` 公开宿主桥 |

**模型文件 / 断点**：仍为 **v8**，本版无格式键变更。
