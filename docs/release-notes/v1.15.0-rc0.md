# neuralnet.cpp v1.15.0-rc0 Release Notes（预发布候选）

> **发布范围**：`v1.14.1`（tag `v1.14.1`，2026-10-31）→ `v1.15.0-rc0`（`feature/kernel-cache`，2026-11-01）。
> **主题**：**引擎 .so 化（双引擎 .so + MIT 抽象层）** + **运行期 JIT 算子缓存（.nnk + kernelgen）** +
> **C++20 模块加载路径（`NN_ENABLE_MODULES`）** + **5 子仓合并回主仓** + **文档工具链**。
> **兼容性**：**有破坏性变更**——引擎实现（LGPL）从主仓头文件移入 `engine/` 子模块并编为
> `libnn-cpu.so` / `libnn-gpu.so`；消费方不再 include 引擎实现头，改链 .so + 工厂
> `create_cpu_engine` / `create_gpu_engine`。新增 CMake 开关 `NN_ENABLE_LTO` /
> `NN_BUILD_TESTS`，删除运行期环境变量 `NN_COPY_FROM_DRAIN`。迁移见 §5。
> **定位**：`rc0` 是 `feature/kernel-cache` 分支的预发布候选。完整四编译器矩阵与 40HX
> 权威口径**未在本次重跑**（本机 Linux clang + libstdc++ + GTX 850M），正式版需按
> [`docs/contributors/release-requirements.md`](../contributors/release-requirements.md) §1–§3 全量重跑。

## 0. 亮点速览（TL;DR）

| 方向 | 变化 | 收益 |
|---|---|---|
| 引擎 .so 化（T9） | 引擎实现（LGPL）编入 `libnn-cpu.so` / `libnn-gpu.so`（新仓库 `compute.neuralnet.cpp`，submodule `engine/`）；抽象层（MIT，`abstraction/include`）C++ 直出——真实 Tensor 值类型跨界（`GpuBuffer` PIMPL，布局与 `NN_HAS_VULKAN` 无关）+ 虚方法分派直落 .so，无句柄映射 / 序列化 / dlopen | 引擎实现可独立替换（LGPL 可替换验证 `bench/lgpl_verify.sh`：改 .so → 不重编消费方 → 行为随 .so 变）；主仓头文件净删 20+ 引擎实现头 |
| 运行期 JIT（Phase 1–3） | `.nnk` 算子缓存（KVRecord v2，K = 生成器版本 + 表达式 → V = SPIR-V）+ `libnn-kernelgen.so`（内嵌 glslang，miss 现编）+ `model_warmup()` 预热；`NN_KERNEL_CACHE_DIR` / `NN_KERNEL_CACHE_PATH` / `NN_KERNELGEN_PATH` / `NN_STRICT_CLOSED_WORLD` 配置 | AOT 闭合世界 → **AOT 注册表预热 + 运行期 JIT 兜底**：未命中表达式不再硬报错，现编可用；`NN_STRICT_CLOSED_WORLD=1` 保留看门狗 |
| C++20 模块 | `modules/nn.{core,kvrecord,dataset,tokenizer}.cpp` 薄接口模块 + 9 叶子消费方双轨（`import` / include）；`NN_ENABLE_MODULES`（顶层默认 ON，嵌入默认 OFF，仅 Clang） | 粒度导入路径（标准符合性 + 精确依赖）；非提速路径（实测见 `research/modules-import-nn/README.md` §6） |
| 子仓合并回主仓 | core / threadpool / kvrecord / dataset / tokenizer 五子仓从 `extern/` 合并回主仓（15 头 + 13 测试）；删 `.gitmodules`、5 个 gitlink、CI submodule 配置 | 消除嵌套 submodule 供货链（一次底层改动需 6 仓 ~10 次 commit/tag 级联）；CONTRIBUTING §4.3 立"不再拆分子仓库" |
| 文档工具链 | `scripts/check_env_vars.py`（环境变量三方对照）+ `scripts/check_header_sync.py`（双仓头一致门禁）+ AGENTS 索引检查 + CI | 双仓（主仓 ↔ engine 子模块）一致性与环境变量口径机器审查化 |

## 1. 引擎 .so 化（双引擎 .so + MIT 抽象层）

### 1.1 目标形态

```text
消费方（主仓 cli / 嵌入工程 / 引擎级测试）：
  #include <neuralnet.cpp/compute_engine.hpp>      # MIT 抽象层（abstraction/include，随 submodule）
  auto eng = nn::create_cpu_engine();              # 工厂（.so 导出，C++ 直出）
  链接：-lnn-cpu  /  -lnn-gpu                      # 引擎实现（LGPL，engine/ 子模块编出）

引擎实现（LGPL，新仓库 compute.neuralnet.cpp）：
  libnn-cpu.so   = compute_cpu_engine + 层/模型头副本 + DSL 求值
  libnn-gpu.so   = compute_gpu_engine + backend/* + 内嵌 SPIR-V + fused 注册表
  libnn-kernelgen.so = 运行期 JIT 算子生成器（shaderc，miss 现编）
```

- 抽象层与引擎实现**同一份头文件编译**（`NN_HAS_VULKAN` 只影响消费方选链哪个 .so，
  不影响抽象层头布局）；`GpuBuffer` PIMPL 化后 Tensor 跨界布局与 `NN_HAS_VULKAN` 无关。
- 主仓 `include/neuralnet.cpp/` 删除与抽象层重复的接口/值类型头（`algebra_*` /
  `compute_engine.hpp` / `compute_tensor.hpp` / `backend/*` / `expr_*` 等 20+ 头），
  保留 MIT 消费侧头（层 / 模型 / 训练 / 数据集 / 分词器）。
- `nn_api.h`（C ABI 门面）保留为薄转发；`bench/lgpl_verify.sh` 提供 LGPL 可替换验证：
  patched .so（matmul 输出 ×2）→ 同一二进制行为随 .so 变 → 复原。

### 1.2 链接面

- 主仓库全部 cli 改链 .so（`NN_GPU_ENGINE` 宏分流链接面）；`cli_engine_factory.hpp`
  改走工厂创建，`--gpu` 选择语义不变（`NN_VULKAN_DEVICE` / `--gpu=<名称>`）。
- `NN_ENABLE_LTO`（默认 ON，需 clang + lld）：Clang thin LTO + LLD，关闭可回退
  （`NN_ENABLE_LTO=OFF`，A/B 或排障）。
- 嵌入消费方（`add_subdirectory` / FetchContent）：门面目标 `neuralnet::nn` 经接口
  传递抽象层 include 路径 / 链接 .so / SPIR-V 嵌入头目录 / Vulkan 链接；嵌入时
  `NN_ENABLE_GPU`、`NN_BUILD_APPS` 语义不变。

## 2. 运行期 JIT 算子缓存（.nnk + kernelgen）

- **Phase 1**：可移植算子缓存 `kernels.nnk`（KVRecord v2）+ `ExprSpec` 序列化器；
  `NN_KERNEL_CACHE_DIR` / `NN_KERNEL_CACHE_PATH` 覆盖系统缓存目录（进程锁防并发写）。
- **Phase 2**：`libnn-kernelgen.so`（内嵌 shaderc）miss 现编 → SPIR-V → 懒建 pipeline →
  执行；`model_warmup()` 跑一遍代表性 forward 把用到的表达式预热进缓存（消费方无
  scan_exprs 注册表时的冷启动消除）。`NN_STRICT_CLOSED_WORLD=1` 恢复硬报错看门狗。
- **表述同步**：文档由「AOT 闭合世界」统一改为「**AOT 注册表 + 运行期 JIT 兜底**」；
  `eval_expr` 主路径 miss 默认 JIT，fold / reduce / into / multi 入口的 miss 仍硬报错。

## 3. C++20 模块加载路径（`NN_ENABLE_MODULES`）

- `modules/nn.{core,kvrecord,dataset,tokenizer}.cpp` = 薄接口模块（全局片段文本包含
  域头 + `export namespace nn { using … }` 逐符号 re-export + `export import` 依赖链；
  DAG `core→kvrecord→dataset→tokenizer`）。
- 构建 = 显式 BMI 自定义命令 + `-fmodule-file` 经 `nn_mod_<域>` INTERFACE 传播；
  开关 `NN_ENABLE_MODULES`（顶层默认 ON，嵌入默认 OFF；仅 GNU 驱动 Clang 生效，
  GCC / cl.exe / clang-cl 自动关闭）。
- **9 个叶子消费者双轨**（`#ifdef NN_USE_MODULES` import / else include）：4 个
  tokenizer/dataset 测试 + 4 个 tokenizer/dataset app + `dataset_integration_test`。
- 硬约束：宏不可导出（消费方显式 include `core_errors.hpp`）、STL 留在全局片段
  （消费方自带 STL 头）、仅 Clang。**非提速路径**（ccache+PCH 基线已压平；价值 =
  标准符合性 + 精确依赖 + 摆脱 PCH），实测见 `research/modules-import-nn/README.md` §6。
- engine / layers / model / train 域依赖 `NN_EXPR_SCAN` 宏收集 → 本轮不模块化。

## 4. 子仓合并回主仓 + 文档工具链

- **5 子仓合并**：`extern/{core,threadpool,kvrecord,dataset,tokenizer}` → 主仓单仓库
  （15 头跨仓 include 全为 `<neuralnet.cpp/...>` 绝对式、文件名不冲突 → 源码零改动；
  13 测试 → `src/`，ctest 72 → 85 注册）。5 个 GitHub 子仓与其历史 tag 冻结为只读存档。
- **文档工具链**：`scripts/check_env_vars.py`（代码读取点 ↔ 文档记载三方对照，无死变量 /
  无漏记）、`scripts/check_header_sync.py`（引擎子模块与主仓副本头一致性）、
  `scripts/doc_audit.py` 增 AGENTS 索引检查；CI 工作流接入。
- **运行期逃生阀删除**：`NN_COPY_FROM_DRAIN`（GPU 录制窗口排空特例）已删除，
  分支 `sync/aot-jit`。

## 5. 破坏性变更 + 迁移指南

### 5.1 消费方链接方式（引擎 .so 化）

| 旧（≤ v1.14.1） | 新（v1.15.0-rc0） |
|---|---|
| include 主仓 `compute_engine.hpp` + 层头，引擎实现随主仓头编译 | include `engine/abstraction/include`（submodule，经 `neuralnet::nn` 接口传递）；链接 `libnn-cpu.so` / `libnn-gpu.so` |
| 引擎工厂在主仓头内（`nn::CpuEngine::create` 等） | 工厂在 .so：`nn::create_cpu_engine()` / `nn::create_gpu_engine()`（抽象层头声明，.so 导出） |
| 引擎实现符号内联进消费方二进制 | 引擎全在 .so；消费方二进制无引擎实现符号（LGPL 可替换） |

迁移步骤（嵌入消费方）：
1. `git submodule update --init engine`（或 FetchContent 指向新仓库 `compute.neuralnet.cpp`）；
2. `target_link_libraries(app PRIVATE neuralnet::nn)` 不变，include 路径 / 链接 / SPIR-V
   目录全部经接口传递，无需手写；
3. 引擎创建改 `create_cpu_engine()` / `create_gpu_engine()`（失败返回 `Result`，错误经
   `last_error()` 取文案）；
4. 需要 GPU 时 `NN_ENABLE_GPU=ON`（缺 Vulkan/glslc 配置期失败）；纯 CPU `=OFF`。

### 5.2 CMake 开关与环境变量

- 新增：`NN_ENABLE_LTO`（默认 ON，Clang+LLD）、`NN_ENABLE_MODULES`（顶层默认 ON，
  嵌入默认 OFF）、engine 侧 `NN_BUILD_TESTS`（默认 OFF）。
- 新增运行期配置：`NN_KERNEL_CACHE_DIR` / `NN_KERNEL_CACHE_PATH` / `NN_KERNELGEN_PATH` /
  `NN_STRICT_CLOSED_WORLD`（均"初始化期读一次 + 缓存"；无探针开销）。
- 删除：`NN_COPY_FROM_DRAIN`（逃生阀，随 AOT 表述同步移除）。
- 行为变化：`eval_expr` 主路径 miss 由硬报错 → JIT 现编兜底；`NN_STRICT_CLOSED_WORLD=1`
  可恢复旧硬报错语义。

### 5.3 仓库结构

- 删除 `.gitmodules` 与 `extern/`（5 子仓合并回主仓）；`engine/` 是新 submodule
  （LGPL 引擎实现，git@github.com:neuralnet-cpp-dev/compute.neuralnet.cpp）。
- `tools/scan_exprs.cpp` / `tools/fused_generate.hpp` 移入 engine 子模块
  （`engine/tools/`）；主仓不再有 AOT 融合构建期工具。

### 6.3 端到端训练（真实语料）

TinyStories 前 5 MB → **5,989 docs / 1,186,978 tokens / 8,016 词**；GPT
`d_model=64 / heads=4 / layers=2 / d_ff=128 / seq_len=64`，`--batch-size 8 --accum-steps 2`，
20 update step，GPU 850M：

| 配方 | loss（step 20） | 结果 |
|---|---|---|
| f32 | 8.8195 → **7.6346** | 健康下降，无 NaN |
| `--f16` | 8.7796 → **7.7236** | 健康下降，无 NaN |
| `--t1_58` | 8.8661 → **8.0099** | 健康下降，无 NaN |

- 断点续训：`--save-interval 5` 的 step10 `.nnckpt` → `--resume` 续 3 步
  **8.3715 → 8.2231**；日志确认优化器 76 张量、`t=10` 恢复、global/micro batch 与
  epochs 恢复；
- warm start：f32 `.nnmodel` 续 1 步，SHA-256 `34d07964…` → `52d68136…`（参数确实移动）。

### 6.4 未覆盖 / 明示风险

1. **四编译器矩阵未重跑**（g++ / libc++ / cl.exe + MSVC STL）：本机仅 Linux clang +
   libstdc++ 一树；40HX 真卡权威口径未在 rc0 覆盖（`scan_bitwise_test` 逐位锚以
   Linux Release + 850M 为权威，本机已全绿）。
2. **Debug 树未跑**（`-O0` 完整 ctest）：rc0 仅 Release；Debug 迭代器断言/`rapt_test_f16`
   稳定性留待正式版。
3. **P3 跨链批量派发 / IR-C 图融合**未在本 rc 变更（沿用 v1.14 能力，本机
   `expr_fuse_test` / `fused_gpu_test` 全绿）。
4. engine 子模块 `tests/`（消费方形态，`-DNN_BUILD_TESTS=ON`）ctest 10/10 在
   submodule 内验证（本机 `build/review/engine` 构建通过）。
