# neuralnet.cpp v1.17.0 Release Notes

> **发布范围**：`v1.16.0`（tag `v1.16.0`，2026-11-02）→ `v1.17.0`（tag `v1.17.0`）。
> **主题**：**C++ 模块迁移收尾（35 号 P0–P6）**——构建无条件走模块、粒度铺到 13 个域、
> BMI 成为消费方 TU 的真实编译依赖、PCH 机制整体删除；叠加 **CPU 表达式折叠（fold）性能**
> （按行并行 / mm 分块内核 / tri_skip 上三角整块跳过）与一批缺陷修复
> （full-f16 图 NaN 根因、退出期 double-free、T1_58 量化缓冲原地化、CLI 引号、环境变量读写统一）。
> **兼容性**：**含破坏性变更**（第 2 位递增）——三个对外接口下线 + 本仓构建支持范围收窄；
> 迁移指南见 §5。

## 0. 亮点速览（TL;DR）

| 方向 | 变化 | 收益 / 结果 |
|---|---|---|
| 模块迁移收尾（P0–P6） | 模块构建**无条件**（删 `NN_ENABLE_MODULES` / `NN_MODULES_ENABLED` / `NN_USE_MODULES` 双轨）；`src/` 79 个 TU 全量 `import`；BMI 经 `OBJECT_DEPENDS` 成为真实编译依赖；PCH 机制整体删除 | 冷构建 ≈15 min；改单个消费方源 ≈79 s；改公共头 ≈35 min（BMI + 消费方 + 链接全量正确重编） |

| full-f16 图 NaN 根因（C1） | Adam/AdamW 状态更新改 `compute_into`（显式落盘）+ 融合器拒绝把 `dst_id != 0` 节点拼为非尾 + into 输出 stamp 恢复依赖；`graph_ok` 门控删除（图恒开） | full-f16 训练（850M）不再 NaN；f32 四成员 `extras=3` 融合保住 |
| 退出期 double-free | MNIST/CNN 默认架构常量改「函数内静态容器 + 引用常量」 | Windows 进程退出 `0xC0000374` 消失（ASan 定位为 `nn::MNIST_LAYER_DIMS` 双重析构） |
| T1_58 原地化 | `quantize_weights_` 的 τ / 打包容器 init 期分配、每步 `compute_reduce_into` / `trit_pack_into` 原地重算 | 每步零新建张量、无瞬态池钉子与延迟销毁 |

## 1. C++ 模块迁移收尾（35 号 P0–P6）

- **P0 命令同源**：`NN_COMMON_COMPILE_OPTIONS` 作为公共编译选项单一真源，`nn_add_module` 的
  BMI 自定义命令按调用方 flags / 配置 flags / Threads 属性 / `NN_GPU_ENGINE` 生成期求值 /
  5 条 `-I` 逐项镜像——消除 `"configuration mismatch"` 类 PCM 加载失败。
- **P1 无条件化**：删除 `NN_ENABLE_MODULES` / `NN_MODULES_ENABLED` 编译器门与
  `NN_USE_MODULES` 宏传播；`src/` 8 处双轨改为无条件 `import`（`tokenizer_consistency`
  经 `tokenizer_test` 文本 include 覆盖，无需单独接线）。
- **P2 宏岛头**：`engine/abstraction/include/neuralnet.cpp/nn_error_macros.hpp` 成为宏段唯一真源
  （`core_errors` / `core_assert` 经其提供宏）；`src/` 68 个宏使用文件显式 `#include`。
- **P3 JIT 预热**：见 §3。
- **P4 粒度模块**：13 域铺满（含 `export using namespace nn;` 命名空间级 re-export，`nn.core`
  60 行逐符号清单删为 1 行）；修 `cli_engine_factory.hpp` 头自包含缺陷（`std::cerr` 只含 `<iosfwd>`）。
- **P5 `src/` 全量 import + PCH 删除**：79 个 TU 全量 `import`（`import` 一律置尾、`using` 随后，
  规避 GMF × 系统头双包含）；链接侧修 `text_train_config` 三函数 `inline`（消费方无文本包含，
  定义须由 BMI 发射）；**PCH 机制整体删除**（`nn_pch` 目标 / `NN_ENABLE_PCH` 开关 /
  presets 候选登记与剔除逻辑）；ccache×模块根因修复：模块消费方目标**禁编译 launcher**
  （ccache 4.13 不支持标准 C++ modules，pcm 内容不进 key ⇒ 会吐旧 `.o`）。
- **P6 BMI 真实依赖**：`nn_use_modules` 把 pcm 经 `OBJECT_DEPENDS` 挂进每个源文件的编译边
  （`add_dependencies` 是 order-only、clang 的 `-MD` 不记 pcm，否则改公共头只重编 BMI、
  消费方 `.o` 陈旧）；configure 期 `nn-gate` 检查 `src/` 残留 `#include <neuralnet.cpp/…>`
  （合法例外仅 `nn_error_macros.hpp` 宏岛头与 STL），正反验证通过。
- **头文件真源**：`model_keyvalue_record.hpp` 主仓副本删除，单一真源迁入
  `engine/abstraction/include/neuralnet.cpp/`（`include` 路径不变，消费方无感）。
- 性能对照（P6，无 PCH 无缓存口径）：改消费方源 **≈79 s** / 改公共头 **≈35 min** /
  冷构建 **≈15 min**。

## 2. CPU 表达式折叠（fold）性能

`eval_fold_impl` 的三段优化（引擎侧提交 7847667 / eaeb934 / c18ed29）：

1. **按行并行（P1）**：行间状态、元素临时、归约槽、行向量态均按行复位 ⇒ 独立分片；
   分片边界只由 `rows/n_chunks` 决定，与调度无关；每片自建 scratch。
2. **mm 段分块内核（P2）**：先整张预计算 `C(row, gk)` 再查表供 `Matmul` 操作数（原为逐
   `(row, gk)` 标量点积且每条引用指令重复算）；复用 `Matrix::multiply_to_span` /
   `multiply_transposed_to_span` / `transpose_multiply_to_span`，语义对齐 `batched_matmul`；
   B 打包取消 16 KB 全量清零。
3. **tri_skip 整块跳过（P5）**：因果掩码下 `qt = row % m_per`，块内 `valid` 截断，
   `valid == 0` 整块 `continue`；恒等论证（跳过项恰为链内 −inf/0 屏蔽值、block0 含未屏蔽对角、
   `fmax(m, lowest) = m` / `exp(0) = 1` / `+0`）保证逐位一致。

实测（`layer_bench`，默认维）：causal_attn fwd **968 → 62 ms**、mha fwd **818 → 83 ms**、
transformer **883 → 117 ms**。

验证：`t1_58` / `expr_cpu` / `ce_fusion` / `f16_precision` / `ternary_gemm` / `write_epoch` /
`bitnet_struct` 共 11 例（含 GPU 变体）全过；行间输出逐位一致。

## 3. JIT 预热接线（P3/D5）

- 运行期：新增 `cli/cli_jit_warmup.hpp`（`model_warmup` 封装，CPU 跳过、失败 `NN_EXIT`）；
  `text_train` / `mnist_train` / `mnist_infer` / `text_infer` 四入口接线，各带
  `--no-warmup` 逃生阀（`text_train` 走 `TrainConfig::jit_warmup`）。
- 构建期：新增 `nn_warmup` 目标（五架构代表性 shape 过 GPU forward → `kernels.nnk`
  落 `--out` / 可执行目录，随发布分发）。
- 实测：mnist 冷 1331 → 热 **148 ms**、text_train 冷 1665 → 热 **535 ms**；
  屏蔽 kernelgen + 预生成缓存下命中（warmup 10 ms、训练完成）。

## 4. 缺陷修复

- **full-f16 图 NaN（C1 根因定案）**：K2（`v` 更新）与 K3/`p+` 同精度融合为单输出 kernel 后，
  `v_[i]` 的占位被内联为融合中间量**从不写入**，下一步读内存池未初始化残留 → `sqrt(负)` → NaN。
  修法三件套：K1/K2 改 `compute_into`（`into` = 落盘声明）、融合器拒绝把 `dst_id != 0` 节点
  拼为非尾、`into` 输出 stamp tag 恢复图内依赖；**门控删除**（`graph_ok` 恒开图）。
  教训入 `docs/contributors/pitfalls.md` §2.6 + 根因模式 I。
- **退出期 double-free**：`domain_mnist.hpp` / `domain_cnn.hpp` 的 `inline` 容器全局同时经模块
  与直接包含头两条路径定义时析构被登记两次（Windows `0xC0000374`，ASan 定位
  `nn::MNIST_LAYER_DIMS`）⇒ 改为函数内静态容器 + 引用常量。
- **T1_58 量化缓冲原地化**：`BitLinear::quantize_weights_` 的 τ 与打包容器 init 期分配、
  每步 `compute_reduce_into` / `trit_pack_into` 原地重算，消除每步新建张量与瞬态池钉子。
- **环境变量读写统一**：删除手写 `getenv` / `_dupenv_s`，统一走 `core_env.hpp`，并由
  `nn.core` 导出读/写入口（`env_*_raw` / `probe_*_raw`）。
- **Windows CLI 引号**：`chat_prompt_test.cpp` 的 `shell_quote` 按 CRT argv 规则翻倍结尾反斜杠
  （助手回复以 `\` 结尾时引号保持打开、后续 `--turn` 被并进同一参数 ⇒ CLI 误报互斥）。
- **Windows + clang（GNU 驱动）+ GPU/模块构建**：`WIN32` 全局 `_CRT_SECURE_NO_WARNINGS`、
  Vulkan 头 `NOMINMAX`、`if(WIN32)` 的 `WINDOWS_EXPORT_ALL_SYMBOLS`、BMI 镜像补
  `-D_DLL -D_MT -Xclang --dependent-lib=msvcrt`、kernelgen 平台名 `nn-kernelgen.dll`、
  `.nnk` 目录自动创建（40HX 实测）。
- **健壮性**：`rd_u64` 越界读先校验缓冲范围；张量分配溢出与 `uint32` 形状截断防线；
  `int8_pack at()` 与 staging-ring 线程模型契约。
- **文档修正**：AOT/JIT、`mem_probe`、优化器名单等 S 级偏差（D1–D14）；自定义层契约补
  `set_training` / `extra_state`（R5）；引擎接口计数 59/38 与实测对齐（D6）。

## 5. 破坏性变更与迁移

### 5.1 模块构建开关下线（`NN_ENABLE_MODULES` / `NN_ENABLE_PCH`）

模块构建与 PCH **不再有开关**，`src/` 一律走模块。

- 迁移：删除 `set(NN_ENABLE_MODULES ...)` / `set(NN_ENABLE_PCH ...)`（或在 configure 传
  `-DNN_ENABLE_MODULES=OFF`）即可——两个变量已不再被读取。
- 嵌入消费方：`NN_BUILD_APPS=OFF` 时模块目标不构建，自身编译与链接口径不变。

### 5.2 `NN_STRICT_CLOSED_WORLD` 移除

严格模式看门狗**删除**（用户裁定不保留旧行为兼容）：运行期 JIT 是唯一的 miss 路径，
`.nnk` 缓存 + `nn::model_warmup()` 预热为性能手段。

- 迁移：不再设置该变量（设置了也无效果）；需要「漏枚举显式失败」的 CI 看门狗，改为
  预生成 `.nnk`（`nn_warmup`）并在无 kernelgen 的环境下跑——JIT 缺失会 `NN_EXIT`。

### 5.3 本仓（`src/` app / 工具 / 测试）构建只支持 GNU 驱动 Clang

`nn_add_module` 用 `${CMAKE_CXX_COMPILER} --precompile` + `-fmodule-file`；cl.exe / clang-cl
没有这两个能力，GCC 也没有 `--precompile` ⇒ **本仓构建**在这些编译器上直接失败。

- 迁移：用 Clang 构建本仓（CI 与发布口径即如此）；原 `msvc-debug` CI job 已随之下线。
- **头文件消费不受影响**：`#include <neuralnet.cpp/nn.hpp>` 不依赖模块，嵌入消费方用自己的
  编译器仍可（MSVC 必须带 `/Zc:preprocessor`，已作为接口选项随门面传递）。

### 5.4 头文件真源迁移（无 API 影响）

`include/neuralnet.cpp/model_keyvalue_record.hpp` 的实体迁到引擎抽象层，`include` 路径
`<neuralnet.cpp/model_keyvalue_record.hpp>` 不变；直接按文件系统路径引用主仓旧位置的工程
需改用 include 路径（正常消费方不涉及）。

## 7. 已知问题

- `tokenizer_test`（C6）：`pre_tokenize` 手写状态机 ↔ `std::regex` 参考实现的 5 处
  `<|...|>` 标记切分差异，源于 clang 24 对「多模块 import × 同 TU 两个 identical static local
  构造」的上游 bug；已在实现侧用 `string_view` 打破同形规避，测试残留差异待上游修复后撤除
  特意差异。
- `rapt_test_f16_gpu`（C11）：RAPT f16 冒烟 NaN（根因未定；Release 不触发只是概率）。
- **边界观察（未改代码）**：`compute_cpu_engine.hpp` 中 `m_per` 兜底（`rows % batch != 0` 时取
  `m_per = rows`）与 `for b < mm_batch` 的写偏移组合在 rows 不可被 batch 整除时会越界；该形态在
  v1.16.0 既有代码中已存在（`eval_expr_impl`），内部调用方恒满足 `rows = batch × 每块行数`，
  故本轮只记录不改。
