## 1. int8 激活量化（W1.58A8，P3 显存侧）

### 1.1 数值口径（docs/internal/21-quantized-weights.md §4.16）

BitNet 训练配方把线性投影的激活量化到 8-bit 整数：

```text
s = col_reduce_max(|X|) · (1/127)          # per-token absmax 尺度，(1,N)
q = round(clamp(x/s, -127, 127))           # round-half-away-from-zero；NaN → 0
Y = (τ∘W)·(s∘Q) + b                        # 量化 GEMM：int32 累加 + 双向量缩放
```

- **s 必须除 127**：原始 absmax 会让 `x/s ∈ [-1,1]`、round 只能落到 {-1,0,1}，
  激活量化分辨率退化成三值（不是 A8）。
- 打包布局 `int8_pack.hpp`：8 bit/元素、4 元素/32-bit 字、行内小端、尾部填 0
  （与 `ternary_pack` 同先例：容器 = f32 张量承载原始字）。
- backward：dX 仍走 `matmul_q_t`（与 f16 路径逐位一致）；dW 的 STE 用反量化激活
  `unpack_i8`（不乘尺度，尺度经表达式折进）+ `(dY∘s)·Qᵀ·τ`。
- 能力：未接 int8 原语的引擎由 `*_impl` 默认实现 fail-fast（与三值打包同款）。

### 1.2 验收

- `src/int8_act_test.cpp`（CPU/GPU）：[1] `quantize_i8` round/clamp 逐位（含 s==0 / NaN）；
  [2] `unpack_i8` roundtrip；[3] `matmul_q_i8` 与宿主整数参考**逐位一致**（含 2B4T 量级形状）；
  [4] forward 差 ≤ 8-bit 量化界；[5] backward STE dW 与宿主参考一致；[6] 端到端收敛。

## 2. AdamWInt8（int8 打包状态优化器）

### 2.1 设计（docs/internal/21-quantized-weights.md §4.19）

AdamWQuant（f16 payload，4 B/权重）再往下的增量是 int8 payload：状态账 8 →
**~2.03 B/权重**（int8 打包 1 B/元素 + 每行 f32 尺度 2×4/cols ≈ 0.016 B，cols=512）。

```text
m_packed = quantize(m_real / sm)          # qm ∈ [-127,127]；|m_real| ≤ sm ⇒ 无溢出
sm_new = max(β1·sm + (1-β1)·row_max(|g|)·1.02, 1e-24)     # 尺度前进（DSL，与 AdamWQuant 逐位一致）
```

- 打包状态 DSL 读不了 → **融合引擎原语 `quantized_adamw_step`**（解码→更新→编码→参数更新
  单内核；否则 f32 全尺寸临时量 4 B/状态 ×2 比省掉的还多）。
- **数值不变量**：`v̂` 下限 = 量化步长 `sv/127`（int8 无次正规兜底：qv=0 时若重建为 0，
  分母退化成 eps → 更新爆炸；下限让最坏比值有界）。
- 断点状态：每参数 4 个张量（m_packed / v_packed / sm / sv）+ `t_`，`save_state`/`load_state`
  往返逐位一致。

### 2.2 验收

- `src/adam_int8_test.cpp`（CPU/GPU）：[1] 原语与宿主参考逐位一致（跨形状）；[2] 状态账
  ≤2.1 B/权重且 < AdamWQuant；[3][4] 收敛 A/B（120 步 MLP：AdamWInt8 loss 0.000147 ≈ f32
  AdamW 0.000165，同量级）；[5] 首步零梯度（尺度下限保护）；[6] save/load 往返逐位一致。
- 参数比较用紧容差（≤1 ULP 舍入容差）：GLSL `sqrt` 精度为实现定义，与宿主 `std::sqrt`
  跨工具链存在 1 ULP 级差异（实测 abs ≤ 2⁻²⁴；m/v 容器纯整数路径仍逐位锁）。

## 3. 免 latent 部署构建（P2 残差根治）

- 推理入口（`text_infer` / `mnist_infer`）按 `role == Model` 以 `inference_only` 形态构建：
  BitLinear init **不分配 f32 latent**（权重由载入的打包字 + τ 接管），层从 packed-only
  只读态起步；载入后 `release_idle_pool_blocks()` 归还解码/中转底材。
- 与文件角色的关系：`role=Model`（.nnmodel）→ `inference_only=true`；`role=Checkpoint`
  （.nnckpt，续训 warm start）→ 正常构建（参数是 latent 形态）。
- 验收：`model_roles_test` [7]「免 latent 构建：inference_only 不分配 latent + 载入后逐位一致」。

## 4. 发布门禁修复（多编译器矩阵）

按 `release-requirements.md` §4 全量重跑四组「编译器 × 标准库」矩阵（各组全新构建 + ctest）：

| 组 | 环境 | 结果 |
|---|---|---|
| clang 24 + libc++ | 本机 Linux + GTX 850M | ctest 81/81（Release）；Debug 80/80（排除既有 C11） |
| g++ 15.2 + libstdc++ | 本机 Linux（portable 口径） | ctest 81/81 |
| cl.exe 19.51 + MSVC STL | 远程 102（VS 2026，Debug，CPU-only） | ctest 81 全绿（GPU 用例 77 skip） |
| clang-cl 23 + MSVC STL | 远程 102（Debug，CPU-only） | ctest 81 全绿（GPU 用例 77 skip） |

矩阵暴露并修复的 7 处问题（全部为发布范围内既有/新增兼容性缺口，已随本版进入 main）：

1. `src/jit_demo.cpp` 注释行尾反斜杠触发 g++ `-Werror=comment`（多行注释续行）；
2. engine `CMakeLists.txt` `std::stacktrace` 探测缺 MSVC 守卫（GNU 库名作
   `CMAKE_REQUIRED_LIBRARIES` 令 MSVC try_compile 直接失败）；
3. engine `CMakeLists.txt` MSVC 下 C++ 标准按主仓口径 `23 + /std:c++latest`
   （CMake 4.3 无 MSVC CXX26 方言映射）；
4. engine `CMakeLists.txt` MSVC 编译旗标适配（`/W4 /O2 /fp:precise` 等，
   GNU 旗标 `-Wextra`/`-O3`/`-march=native` 令 cl 报 D8021）；
5. engine SHARED 目标加 `WINDOWS_EXPORT_ALL_SYMBOLS`（无导出符号时 cl 不生成
   `.lib` 导入库，链接方 LNK1104；与 Linux .so 默认全导出对齐）；
6. `src/kernel_cache_test.cpp` `setenv`/`unsetenv` 加 Windows 适配
   （`_putenv_s` 空串 = 删除，MSVC 无 POSIX 函数致目标无法构建）；
7. `src/assert_test.cpp` 子进程命令加 `cmd /c` 前缀（MSVC `system()` → `cmd /c`
   的命令以引号开头触发首尾剥除规则，内层引号失衡致子进程不执行）。
