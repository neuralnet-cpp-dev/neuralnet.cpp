# neuralnet.cpp v1.8.1 Release Notes

> **发布范围**：`v1.8.0`（`afcb3d0`，2026-10-11）→ `v1.8.1`。
> **主题**：**代码审查整改（RV-06 … RV-13）** + **CI 真跑测试与绑定不变量门禁** + **工程化（预设构建 / 格式与贡献指南 / 文档归档）** + **编译提速（ccache × PCH）**。
> **兼容性**：**无破坏性 API 变更**——引擎接口与 virtual 计数不变、`get_*_spirv()` 名称与签名不变、`create_tensor` 签名保留（新增 `try_create_tensor`）、Layer/Loss/Optimizer/Model 公共入口无删除。逐条裁决与验收证据见 [`../internal/00-code-review-remediation.md`](../internal/00-code-review-remediation.md)。

## 1. 算子分派单一表（RV-07）

- 新增 [`include/neuralnet.cpp/expr_op_table.hpp`](../../engine/abstraction/include/neuralnet.cpp/expr_op_table.hpp)：以 [`algebra_ops.hpp`](../../engine/abstraction/include/neuralnet.cpp/algebra_ops.hpp) 的 `nn::ops::*::apply` 为 **CPU 标量语义**，每个 `ExprOp` **一行**元数据 = 元数 / 归约标志 / 可折叠性 / 一元·二元函数指针 / GLSL 发射形态 + 符号 + 向量比较内建名。
- 表尾 `consteval expr_op_table_consistent()` + `static_assert` 强制本表与 `expr_spec.hpp` 的 `expr_instr_num_operands` / `expr_op_is_reduce` / `expr_op_reduces_cols` 逐项一致——写漏同步即**编译失败**。
- 原先的分派点全部改查表：
  - CPU 引擎（`compute_cpu_engine.hpp`）三处 switch：fold 标量求值 + 两处寄存器融合；
  - [`expr_opt.hpp`](../../engine/abstraction/include/neuralnet.cpp/expr_opt.hpp) 的常量折叠；
  - [`expr_glsl_gen.hpp`](../../engine/engine/include/neuralnet.cpp/expr_glsl_gen.hpp)：删掉 `glsl_binary_op` / `glsl_unary_op` 两个符号表函数，改为单一发射器 `glsl_alu_expr`，**6 处**指令发射块（标量主链 / `emit_assign` / 内联 `expr_inl` / 折叠段 / `emit_scalar_chain` / vec4 快路径 / `emit_instrs`）共用它。
- **纯重构**：融合 shader 的 GLSL 源码与 SPIR-V **逐字节不变**（口径见 §5）。

## 2. VK 后端拆分 + SPIR-V 注册表（RV-08）

- **getter 表驱动**：42 个 `get_*_spirv()` 的手写 `#ifdef … / #else static empty / #endif` 函数体、以及 42 个 `#define NN_*_SPV_EMBEDDED` 全部删除。文件头的 `#if __has_include("<name>_spv.hpp")` 探测块改为把字节码绑到 `NN_SPV_FN_<name>`（有嵌入头 = 真实函数；纯 CPU 构建 = `detail::spirv_missing()` 占位空向量），`GpuBackend` 内用 `NN_SPV_GETTER_LIST(NN_SPV_GETTER)` 一次展开出全部 getter。**42 处调用点零改动**（`get_<name>_spirv()` 名称与签名不变）。
- **物理拆分（纯移动、零行为变化）**：`GpuBackend` 成员体（~5375 行）拆为 4 个**片段**文件，由主文件在 `class GpuBackend { … }` 体内**按序** `#include`：

  | 片段 | 内容 | 行数 |
  |---|---:|---:|
  | `backend/compute_vk_backend_destroy.inc` | 延迟销毁决策/入口、reap 单帧、pipeline 句柄、收帧、显存回收 | 954 |
  | `backend/compute_vk_backend_frame.inc` | 帧环 / batch / 阻塞上传下载 / 通用 dispatch / matmul | 785 |
  | `backend/compute_vk_backend_pipelines.inc` | RLA 扫描原语 + 描述符集 / 跨 submit 依赖 / solo fence / 屏障 | 648 |
  | `backend/compute_vk_backend_ops.inc` | 各原语 dispatch | 2687 |

  主文件 **6397 → 1055 行**；片段均 < 3000。
- ⚠ **片段不是独立头**（不可单独编译）；包含路径与 `compute_vk_backend.hpp` 同目录，`add_subdirectory` / 打包整树时自动带上——**手工只拷单个头文件的人要连 4 个 `.inc` 一起拷**。
- ⚠ 片段内 `#include` 是本仓首次使用的「单类跨文件」手法（`GpuBackend` 是单一类，纯移动只能走此路）；若日后倾向拆成多个协作类，属非纯移动，须单独立项。

## 3. 环境变量 / 精度护栏 / 概念位置（RV-09 · RV-11 · RV-13 · RV-10）

- **RV-09 环境变量单一入口**：新增 [`core_env.hpp`](../../engine/abstraction/include/neuralnet.cpp/core_env.hpp)（`nn::detail::{env_flag_raw, env_string_raw, env_int_raw}` + 探针门包装 `{probe_flag_raw, probe_string_raw}`）。四处 helper 全部改为转发：`expr_dsl.hpp::dsl::env_flag`、`compute_engine.hpp::{prec_env_flag, prec_trace_enabled_, bind_debug_enabled_}`、`core_profile.hpp` 的全局开关、`backend/compute_vk_device.hpp::VulkanDevice::get_env`。MSVC `_dupenv_s` 分支只此一份；探针门下的开关在 `NN_ENABLE_PROBES=OFF` 时**恒 false 且不求值 `getenv`**（AGENTS §2 的两层语义不变）；口径统一为"存在、非空、首字符 != `'0'`"。
- **RV-11 精度映射护栏**：`precision.hpp` 加 `static_assert` 冻结「枚举值 ↔ 序列化 tag」两张映射，并断言 `precision_from_tag(precision_tag(p)) == p` 往返——改一处即编译失败。
- **RV-13 概念归位**：`nn::Expression` / `nn::BoolExpression` 从 `expr_dsl.hpp` 移到 L1 的 `algebra_span.hpp`（`expr_dsl` 经 `algebra_matrix → algebra_span` 传递可见，源码兼容）。
- **RV-10**：BitLinear 量化判据注释精确化（**严格** `|W| > 0.5τ`、恰好半值归零）——只改注释，算法未动。

## 4. 绑定不变量与 CI（RV-06 · roadmap P0-1）

- **前置去红**：`NN_BIND_DEBUG=1 ctest` 原为红（`t1_58_test` / `ternary_gemm_test` / `model_roles_test` 三例报 "unbound input into engine"）——根因是 `matmul_q_impl`（CPU 与 GPU 两份）在边界 cast 回退里，对**尚未 stamp** 的产物直接调**公共** `cast`（内含 `bind_check_`）。两处改为 `cast(adopt(std::move(x)), P)`。
- **CI 升为门禁**：`cmake-single-platform.yml` 配置加 `-DNN_ENABLE_TESTS=ON`；Build 后新增 **6 类** ctest 步骤（Linux/Windows × 普通/`NN_BIND_DEBUG=1`，均 `--output-on-failure`）。需 GPU 的用例在无 GPU 的 runner 上按退出码 77 记 skip（非失败）。
- **打包补齐**：Linux/Windows 的 7z 产物加入 `dataset_gen` / `dataset_convert`（应用入口 6 → 8）。
- **顺带修的真实缺陷**：`src/assert_always_test.cpp` 的裸 `std::fopen` 在 clang++ + MSVC STL + `-Werror` 下编译失败（正是 CI 的 Windows 配置，此前不编测试故未暴露）→ 改 `_MSC_VER` 下 `fopen_s`。
- **无卡环境的 SKIP 口径补齐**：`gpu_test` / `gpu_f16_test` / `gpt_offload_test` / `fused_gpu_test` / `ce_fusion_test`（含经 `expr_gpu_test` 复用的 `fused_gpu_test`）原先只在**未编译 Vulkan** 时返回 77；CI runner 编了 Vulkan 但**没有设备**，于是硬失败（`vkCreateInstance failed: -9`）。现统一为「**Vulkan 后端初始化失败 → 77 = ctest SKIP**」（与 `cnn_test` / `batchnorm_test` / `write_epoch_test` 同一约定）；另外 `gpu_f16_test` 的纯 CPU 分支由 `return 0` 改为 `return 77`（原先会把"没跑"记成 Passed）。

## 5. 工程化、编译提速与文档整理

- **预设构建**：新增 `CMakePresets.json` —— `release` / `dev` / `debug` / `portable` / `cpu` / `probes` 六个 preset，外加 `build` / `test` / `workflow`（`cmake --workflow --preset dev` 一条命令走完）。`binaryDir` = `build/<preset名>`；**preset 不改变 CMakeLists 的默认值**（不带 preset 的 `cmake -B build -G Ninja` 行为逐字不变）。
- **ccache × PCH**：ccache 缓存"用了 PCH 的 TU"要求 Clang 侧三项齐备。前两项（`sloppiness=pch_defines,time_macros` + `-include-pch`）由构建系统用 `cmake -E env` 钉进 `RULE_LAUNCH_COMPILE` 前缀（**不依赖用户全局 ccache 配置**），第三项 `-fno-pch-timestamp`（必须 `-Xclang` 形式）自动加到 PCH 生成方与全部使用方。修复前每个用 PCH 的 TU 都记 "Could not use precompiled header" → **42+ 个目标全部不可缓存**；修复后同一 TU **30.2s → 0.11s**。顺带删掉 `RULE_LAUNCH_LINK`（本项目不做 LTO）。
- **风格与贡献入口**：`.clang-format`（目标风格，**不要**整仓重排）/ `.editorconfig` / `.gitattributes`（全仓 LF）；`CONTRIBUTING.md` + `CODE_OF_CONDUCT.md`；`research/README.md` 索引。
- **文档整理**：`history.md` 迁入 `docs/history/history.md` 并成为**全仓唯一历史归档**（演进记录 / 已修复勘误 / 被否决方案 / 性能 A/B）；`AGENTS.md` 精简重写为"只记当前状态"；`docs/README.md` 与各分册索引同步。
